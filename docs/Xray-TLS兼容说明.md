# Xray TLS 版本兼容

核对日期：2026-10-16。

Trojan 分享链接缺少 `security` 时，默认仍应启用 TLS。这是订阅导入问题，与是否跳过证书验证是两个独立设置。公共导入和旧配置读取层补齐默认 TLS 后，三个核心都能收到正确的传输安全类型。

## 设置优先级

设置第一页的“默认允许不安全 TLS”仅在节点未明确指定证书验证设置时生效。节点自身的 `allowInsecure=true/false` 优先于该默认值，已有可信证书或指纹则优先用于验证。

sing-box 将结果写入 `tls.insecure`；Mihomo 写入 `skip-cert-verify`。Xray 能否接受跳过验证，取决于实际启动的核心版本及运行时 UTC 时间。

## 版本边界

| 已核对版本或范围 | `allowInsecure=true` 的行为 |
| --- | --- |
| 1.8.24、24.12.31、25.3.6、25.6.8、25.9.11、25.10.15、25.12.8 | 支持 |
| 26.1.13、26.1.18、26.1.23 | 支持，其中后两个版本会输出弃用提示 |
| 26.1.31、26.2.2 | 直接拒绝 |
| 26.2.4 至 26.6.1 的已发布标签 | 2026-06-01 00:00:00 UTC 之后拒绝；此前允许 |
| 26.6.22 至 26.10.10 的已发布标签 | 直接拒绝 |

来源：[26.1.23](https://github.com/XTLS/Xray-core/blob/v26.1.23/infra/conf/transport_internet.go)、[26.1.31](https://github.com/XTLS/Xray-core/blob/v26.1.31/infra/conf/transport_internet.go)、[26.2.4](https://github.com/XTLS/Xray-core/blob/v26.2.4/infra/conf/transport_internet.go)、[26.6.22](https://github.com/XTLS/Xray-core/blob/v26.6.22/infra/conf/transport_internet.go)、[26.10.10](https://github.com/XTLS/Xray-core/blob/v26.10.10/infra/conf/transport_security.go)。这些边界针对官方核心；未知版本不能假定支持跳过验证。

## 配置适配

- 代理启动、单节点测速和批量测速都从此次使用的 Xray 可执行文件探测版本，应用同一兼容检查。测速模板清空协议策略后，配置生成仍沿用已解析的启动核心，避免自动回退到其他核心的配置格式。
- 支持跳过验证的版本保留原设置。已不支持的版本若缺少可信证书或指纹，提前提示补充可信信息或使用其他核心，不自动信任网络上取得的证书，也不静默切换核心。
- `pinnedPeerCertSha256` 从 26.1.13 起支持；26.1.13 至 26.1.23 的多个指纹使用 `~` 分隔，26.1.31 起使用英文逗号。适配层校验每个 SHA-256 指纹、统一大小写和冒号格式，并生成目标版本接受的分隔符。
- 早期版本的 `pinnedPeerCertificateChainSha256` 是证书链散列，不能把叶证书散列直接改名写入。对不支持叶证书指纹的旧核心明确提示升级或配置可信证书，避免未知 JSON 字段被忽略后造成“看似锁定、实际未验证”。
- 兼容检查失败时，不覆盖现有运行配置文件；批量测速单独报告不兼容节点，避免它们导致整个批次的核心启动失败。

指纹校验规则来源：[官方 TLS 文档](https://github.com/XTLS/Xray-docs-next/blob/main/docs/config/transports/tls.md)。

## 验证范围

已使用 Windows 官方核心 25.12.8、26.1.23、26.1.31、26.2.2、26.3.27、26.10.10 运行配置预检，并通过真实可执行文件验证应用的版本探测、配置适配及不兼容节点的单独与批量测速拒绝路径。25.12.8、26.1.23 对同一个原始受影响节点补齐 TLS、保留跳过验证后，实际请求均返回 HTTP 204。时间边界、未知版本、错误指纹、设置优先级和中文翻译另由独立测试覆盖。

配置预检通过只证明核心接受配置，不代表远端证书或节点连通性通过。可信指纹必须来自用户或服务提供者的可信渠道；当前缺少指纹且证书与 SNI 不匹配的节点，在新版 Xray 下仍应明确拒绝，不宣称已恢复连接。
